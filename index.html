1. UniFi Networking System

1.1 Ethernet Infrastructure

WAN、网关、交换、Wi‑Fi、Room Drop 与线材的选型与适配。端口落点与连线见 Topology；本节只写型号能力与适配性。

1.1.1 ISP

正式套餐为 Telus PureFibre 5 Gig（标称 5 Gbps）。入户是一根光纤；机柜里只要一台运营商光终端，把光信号转成一根 10G 网线进 Dream Machine Pro Max，本宅不另买光电转换盒。客户侧这条网线必须能跑到 5G 或 10G，否则套餐会被口速卡死。

多千兆 PureFibre 用的是较新的 XGS-PON（对称约 10 Gbps 级的光纤接入）。旧套餐常见 GPON（约千兆级）。机柜极简优先要独立 ONT；默认发给用户的往往是更胖的 Network Access Hub（NAH）——两者怎么取舍见下方。

  • 机柜定稿（极简优先）：开通 / 上门时点名要独立 Nokia XS-250X-A（XGS-PON ONT：无 Wi‑Fi，常见 1×10G + 4×1G 电口；本宅只用 10G）。光纤进 ONT，10G 口短跳 Cat6 → UDM。订单备注写清「standalone Nokia XS-250X-A bridge ONT / enterprise firewall」；库存与技师意愿不保证，拿不到再退回 NAH。
  • 回退：若只装到 NAH（常见 NH20A / NH20T），开 Port 10G Bridge，同样 10G 短跳进 UDM。功能上与独立 ONT 等价，只是机柜多一台更占位的盒子。不要 ONT 与 NAH 叠两台（有 Optik / 座机时技师有时会这么装）——本宅不依赖运营商电视 / 电话进机柜时，坚持只要一台光终端。
  • 链路（ONT 或桥接后的 NAH 相同）：运营商光纤 → TELUS 光终端 → 柜内短 Cat6 → Dream Machine Pro Max 的 SFP+ WAN。SFP+ 是可插拔模块槽；这里插 SFP+ to RJ45 Adapter（把槽变成 1/2.5/5/10G 电口）。光终端对外是 10G 电口（RJ45）；柜内短跳不会降速。WAN = 外网侧；LAN = 家里内网侧。
  • 不要把光终端的 10G 网线直插 UDM 面板上那个 2.5G WAN 铜口——只会协商到 2.5 Gbps，5 Gig 吃不满。必须走 SFP+ WAN + 多速率模块。
  • 能否把光纤直接插进 UDM、干掉所有 TELUS 盒子：旧 GPON 上有时可行（笼子里的模块本身是已登记 ONT）。本宅 5 Gig 是 XGS-PON：局端（OLT）认证的是运营商光终端整机序列号，笼子里的模块多半只是光口零件。客服 / 技师也不能把 UDM 机箱序列号登记进 OLT——局端认的是 PON ONT 身份，UDM 不会说 PON。第三方仿冒 ONT 不受支持，本 Spec 不做。机柜极简的上限是「一台 TELUS 光终端 + UDM」，不是零运营商设备。
  • 若落到 NAH，模式怎么选：
    • Router（路由）：默认。NAH 自做 NAT / DHCP / 防火墙；后面再挂 UDM = 双 NAT。不要。
    • Port 10G Bridge：只把 10G 口透传成 WAN，公网落到 UDM。回退定稿。
    • Port 1 Bridge：桥的是 1G 口，不够 5 Gig。
    • Full Bridge：所有口暴露给运营商侧；家用动态公网 IP 少，且下游都要自己扛防火墙。本宅只需一条进 UDM 的 WAN。
  • 分工：光终端（XS-250X-A，或桥接后的 NAH）只做光纤→网线；路由、防火墙、VPN、UniFi 全部交给 Dream Machine Pro Max。公网地址一般由 UDM 用 DHCP 取得（少数地区 PPPoE，按开通单）。后级交换与 Wi‑Fi 见 Gateway / Switching / WiFi。

1.1.2 Gateway

机柜网关定为 Dream Machine Pro Max：UniFi OS 一体机，承担路由、威胁管理、统一控制面，并内建 Protect / Access / Network 应用托管。

  • WAN：SFP+ 插 SFP+ to RJ45 Adapter 接 TELUS 光终端（优先 XS-250X-A；回退为桥接 NAH），对齐 PureFibre 5 Gig；勿用 2.5G 铜 WAN。
  • LAN：Dream Machine Pro Max LAN SFP+ ↔ Pro XG 24 PoE SFP28，机柜内用 10G Direct Attach Cable（10G DAC）。短、稳、不占铜口。
  • 为何是 Pro Max：需要同时扛多应用（Network + Protect 录像调度 + Access）与 10G WAN/LAN；家用一体机里口速与应用密度匹配本宅，不必再拆独立安全设备。
  • 供电：市电；不占 PoE 预算。机柜回路应在 Powerwall whole-home backup 内（备电策略见 §4）。

机柜 NAS（Synology FS2500）见 §3 Home Office Setup；交换侧仅预留其 2×10G LACP 上联。

1.1.3 Switching

有线核心是一台机柜汇聚 + 两台房间/车库边缘交换机。两台边缘交换机都不直连机柜铜口：各自走本室 Room Drop（Media / Garage）home-run 到配线架，再 patch 进 Pro XG 24 PoE；墙口再用短跳接到 Flex 的 10G RJ45 上联口。两台 Flex 上联均只用 10G RJ45（不用 combo 上的 SFP+），并由该口经 PoE 供电；不接墙端 AC、不装随附 / 可选 AC 适配器。选型看口速、PoE 等级与是否需要下游供电，端口表见 Topology / §1.3。

  • Pro XG 24 PoE：16×10G + 8×2.5G，铜口均可 PoE+++（802.3bt Type 4），交换侧 PoE 预算 720W；另有 SFP28 上联（接 Dream Machine Pro Max）。负责 AP、门禁上行、HA / Wallpanel、各 Room Drop（其中 Media / Garage 两路在远端喂两台边缘 Flex 并为其供电）与 NAS LACP。市电供电，720W 是输出预算不是墙端功耗。
  • Flex 2.5G（Media，非 PoE 输出）：经 Media Room Drop 接到机柜 Pro XG 24 PoE。上联仅用 10G RJ45（SFP+ combo 口空闲），并由该口吃 PoE+ input（整机最大约 14W）；不接随附 5V USB-C，不接 AC。八个 2.5G 下联口只传数据、不供电。Media 室需要多口有线但不需要边缘 PoE，因此明确不用 PoE 输出版。
  • Flex 2.5G PoE（Garage）：经 Garage Room Drop 接到机柜 Pro XG 24 PoE。上联仅用 10G RJ45（SFP+ combo 口空闲），并由该口吃 PoE+++ 供电（短线厂商可用下游约 76W）；不接 AC Adapter 210W，不接墙端 AC。八个 2.5G 下联可 PoE。车库边缘有 U7 Lite、Door Hub Mini、SuperLink Gateway 等 PoE 负载，故必须用 PoE 版。

1.1.4 WiFi

主屋覆盖：Basement / Main / Upper 三层墙面 U7 Pro Wall ×3（配 U7 Pro Wall Paintable Flush Mount）；车库一台 U7 Lite。U7 Pro Wall 以 2.5G / PoE+ 级口速与 Wi‑Fi 7 能力服务主屋；U7 Lite 覆盖车库与车道侧，功耗与口速更低，适合挂在 Flex 2.5G PoE 下。

  • 固定终端原则：有网口、固定位置、在意延迟或 NAS 大流量 → Ethernet（Room Drop / 房间交换机）；手机、平板、笔记本、多数 IoT → Wi‑Fi。把电视墙、游戏机、Mac Studio 挪出无线后，airtime 留给移动设备。
  • 适配性：三层主屋统一墙面 U7 Pro Wall（Flush Mount）；车库单独 U7 Lite，避免用主屋 AP 硬打穿混凝土/金属门。

1.1.5 Room Drops

七个房间（Media / Den / Master / BR1 / BR2 / Seating / Garage）各拉两根 Cat6A 实心铜 home-run 到机柜配线架，完整通道按 Type 4 / 4PPoE 选材，全部终结、认证、贴标。除 Den 外每间只启用一根；备用线占配线架，不占交换机口。Den 两根全开、各占一口。Media 与 Garage 的在用口在远端接边缘 Flex，再经该 Room Drop 回到机柜 Pro XG 24 PoE——不是另拉一条「交换机上联」进柜。

  • Den：墙面双口 plate，两根均启用。一口接 Mac Studio（机身 10GbE），配线架 patch 进 Pro XG 24 PoE 的 10G 口；另一口接 §2.1 HA Hub（ameriDroid PoE Mini PC），配线架 patch 进同一交换机的 2.5G PoE+++ 口（机身 PoE++ IN）。同室长期桌测 Wallpanel（第四套）不另占 Room Drop、也不上 Den Flex：数据走 Hub 空闲 2.5G，供电走桌面 PoE+ 注入器（见 §2.2）。拓扑图暂未改，以本 Spec 为准。
  • Media / Garage：墙面单口。Media 在用口经短跳接 Flex 2.5G 的 10G RJ45 上联；Garage 在用口经短跳接 Flex 2.5G PoE 的 10G RJ45 上联。第二根留在墙盒 / 配线架作冗余，不做出第二插口以免误插。
  • 其余四间（Master / BR1 / BR2 / Seating）：墙面单口；第二根同样只留在墙盒 / 配线架。
  • 面板采购：横向双口一包（Den）、纵向单口两包（其余六间墙面 + 余量；官网每包 4 只）；keystone 用 Cat6A Keystone Jack, 12-Pack。机柜端用 24-Port Blank Keystone Patch Panel（1U / 19″，开放架即可，不依赖 UniFi 机柜）。
  • 扩展路线（按需升级，不提前每间装交换机）：① AP + 1×C6A → ② 该 C6A 上联房间交换机 → ③ 两根都进同一交换机时必须 LACP 或 STP，禁止随手双接成环（Den 已是两台不同终端各占一口，不是双接成环）。其它房间若以后要双口，再换面板。
  • Mechanical Room：机柜已在本室，不再做「卧室式 Room Drop」。需要时从配线架就地短跳到 HVAC / 热水 / 集水坑控制区（默认不 patch 进 Pro XG 24 PoE）。

1.1.6 Cables

全项目铜缆统一按 IEEE 802.3bt Type 4 / 4PPoE 完整通道选材与验收（线缆、跳线、keystone、配线架、端接）。Type 4 是供电承载能力，不改变 Cat6 / Cat6A 的数据类别；无 PoE 或低功率口仍只按设备协商，不会被强制送 90W。

  • Cat6A 实心铜：永久入墙 / home-run（Room Drop、主屋 Door Hub Mini、AP、Wallpanel、Protect Viewport、Garage Room Drop 等），保证百米级 10G 与余量。
  • Cat6 短跳：柜内 TELUS 光终端→Dream Machine Pro Max、Pro XG 24 PoE→HA / NAS、墙口→Flex 2.5G / Flex 2.5G PoE、Door Hub Mini→读头/摄像头、Flex 2.5G / Flex 2.5G PoE 下联、Tesla 以太网等短距离；短跳不限速这些链路，但须为纯铜、24–26 AWG、Type 4 额定。禁用 CCA / 未标定细径线。
  • 光 / DAC：Dream Machine Pro Max↔Pro XG 24 PoE 用 10G Direct Attach Cable。
  • 非以太网：门锁 LOCK 为 Wet 12V 控制线；DPS 为干接点门磁（本宅 Securitron DPS）；Tesla 控制为 CAN——不要用网线标准去套这几类。

1.2.2 Security CCTV

门口摄像头挂在各门 Door Hub Mini 下（见 Exterior Door）。墙端 Protect 监视与通用显示器选型分开：监视走 UniFi Protect 专用机，不用电脑显示器 + 第三方 App 充当常驻预览。

  • 监视器：Protect Viewport
    • 位置 Main / Kitchen
    • 本机 1G PoE（约 9.5W）
    • 上行 Pro XG 24 PoE 直供，不经过 Door Hub Mini
  • 用途：实时预览与门口操作；录像仍由 UniFi Protect（Dream Machine Pro Max）承担，不以 HA 或通用显示器取代 NVR。

1.2.3 Garage Gate

车道大门 / 电动门禁位，与 Garage Door（车库行人/车门）分开记账。控制与读头型号待定；选定前不占用 Door Hub Mini 端口，也不并入现有五套 Door Hub Mini 子树。选型时须单独定：是否需要 Access Hub、锁体/电机干接点、读头 PoE 接口等级，以及上联落在 Flex 2.5G PoE 还是日后 Utility Switch。

1.2.4 USL

SuperLink Gateway 是 SuperLink / BLE 网关，不是传感器：100M PoE，由 Flex 2.5G PoE 直供，不经过 Door Hub Mini。

  • 传感器：Environmental Sensor 电池供电，测漏水 / 温湿度 / 环境光，经 SuperLink（北美约 915 MHz）回 Gateway，无需 Ethernet。
  • 布置：Gateway 挂车库半高墙、避大金属面；Environmental 放集水坑、热水器、冷热水汇管附近即可。
  • 覆盖：地下室混凝土与炉体可能衰减 915 MHz。若 Protect 里传感器不稳，再在 Mechanical Room 加第二台 SuperLink Gateway（同样 100M PoE），就地短跳，仍不要经 Door Hub Mini。

2.4 Protocols

协议层决定设备怎么进 HA、掉线时从哪一层查。射频硬件（ZBT-2×2 + ZWA-2）落在 §2.1 Den Hub；本节只写各协议角色。IP 侧（Wi‑Fi / MQTT / Matter-over-Wi‑Fi）不另买棒。

2.4.1 建议追加（按需，非 Day-1）

  • ESPHome Bluetooth Proxy（Ethernet / PoE）：即使 Hub 在 Den，全屋 BLE 仍靠房间级 Proxy。按楼层放 1–2 台以太网 ESP32（优先外置天线，如 Olimex ESP32-PoE-ISO-EA 一类），专做 BLE 广告与短连接；不要拿 ZWA-2 兼 BLE 主力。
  • 厂商 Bridge（有才买）：Lutron Caseta / RadioRA、部分窗帘与红外空调仍要自家网桥或 IR blaster；通用 802.15.4 棒吃不下私有射频。
  • IR blaster（ESPHome / Broadlink 等）：仅当一楼仍有大量红外-only 空调 / 音响、且无云控本地方案时再补；优先买原生局域网 / Matter / Zigbee 设备。
  • 不需要：第二套 Zigbee 协调器、Hub 上再插 USB Wi‑Fi 棒、Thread 再买第三根 ZBT-2（除非日后要独立实验室网络）。

2.4.2 Z-Wave

角色：门锁、部分墙开 / 插座、对穿透与干扰更敏感的「关键控制」设备的主射频之一；与 2.4 GHz 家用 Wi‑Fi 错开（Sub‑GHz）。本宅用 ZWA-2 + Z-Wave JS。

  • 优点：墙体穿透通常好于 2.4 GHz mesh；认证设备互操作规范；LR 适合大宅庭院距离；不占 Wi‑Fi airtime。
  • 缺点：北美 / 欧频不通用，出国淘货易买错频；生态体量小于 Zigbee；新设备价格偏高；mesh 仍依赖插电路由节点。
  • 品质与掉线：认证锁与老牌墙开（Zooz / Inovelli / Yale 等社区口碑线）稳定；杂牌「名义 Z-Wave」固件差会导致莫名离线。掉线优先查：天线座是否开阔、路由节点是否被拔掉、是否混入错误频段设备、控制器附近 USB 3 噪声。
  • 地位：与 Zigbee 并列的「本地控制」骨干，不互相替代；门锁优先看 Z-Wave / 已有 UniFi Access，不优先 Wi‑Fi 云锁。

2.4.3 Zigbee

角色：传感器、灯泡、开关、插座数量最大的本地 mesh；第一根 ZBT-2 + ZHA（日后若兼容性逼仄再评估 Zigbee2MQTT）。

  • 优点：设备便宜、选型多；有电路由节点一开，电池末端跟网；不进家用 Wi‑Fi；ZHA 零基础路径短。
  • 缺点：与 Wi‑Fi / Thread 同处 2.4 GHz，信道要规划；厂商私有 cluster（部分 Tuya）在 ZHA 上功能残缺；mesh 质量取决于「家里插电 Zigbee 设备密度」，不是协调器标称距离。
  • 品质与掉线：IKEA / Hue / Aqara（注意桥与直连差异）/ Sonoff 官方 Zigbee 等主流线更稳；白牌电池传感省电激进、隔墙掉线常见——用插座 / 灯作路由骨架后再放末端。协调器天线塞进封闭金属腔是最需要避免的人为掉线。
  • 地位：默认「小数目常在线设备」首选；能 Zigbee 就不要堆 Wi‑Fi IoT。

2.4.4 Thread

角色：低功耗 IPv6 mesh 传输层，主要承载 Matter-over-Thread 设备；第二根 ZBT-2 做 HA 自有 Border Router，不依赖 HomePod / Nest 是否在线。

  • 优点：为电池设备优化；IP 地址可直达（经 Border Router）；Matter 生态主推路径之一；多 Border Router 时可提升冗余（日后 Apple TV / Nest 可作辅，但本宅以 HA 棒为准）。
  • 缺点：Thread 本身不是应用层——没有 Matter / 厂商应用就「裸 Thread」对用户无意义；前期设备贵、调试信息少；与 Zigbee 同频干扰要分开天线与信道策略。
  • 品质与掉线：Matter 认证电池设备近年明显好转，但仍见固件入网失败、迁移网络后变砖；掉线常见于 Border Router 断电、IPv6 / mDNS 被 VLAN 防火墙误伤、只用一根 BR 且位置极差。
  • 地位：新买电池类 Matter 设备的传输首选；不取代现有 Zigbee 库存。

2.4.5 Wi‑Fi

角色：高带宽或厂商只给了 Wi‑Fi 的设备（部分摄像头配件、电器、Matter-over-Wi‑Fi）；本宅无线由 UniFi AP 承担，HA 不另建 Wi‑Fi。

  • 优点：人人会配；吞吐高；Matter-over-Wi‑Fi / 局域网 HTTP 集成简单。
  • 缺点：占 AP airtime；每台设备一个 DHCP / 固件攻击面；云依赖机型断云即残；2.4 GHz 拥堵时与 Zigbee / Thread 互害。
  • 品质与掉线：本地 API 清晰的品牌（部分 ESPHome 刷机设备、严谨局域网家电）可用；Tuya 云灯 / 杂牌插座是掉线与隐私重灾区。能有线（Room Drop）的固定设备不要走 Wi‑Fi。
  • 地位：补充通道，不是传感器主干；IoT SSID / VLAN 可后续拆，Day-1 以少而稳为先。

2.4.6 Bluetooth（含 BLE）

角色：短距传感器、部分体脂秤 / 温湿度 / BTHome 设备、手机存在探测的辅助；靠房间级 Bluetooth Proxy 延伸，不靠 Hub 机身 BLE。

  • 优点：设备门槛低；BLE 广告传感功耗极低；ESPHome Proxy 与 HA 集成成熟。
  • 缺点：墙体衰减狠、无 mesh；活跃连接数有限；与 2.4 GHz 其它射频共存压力大；安全配对体验参差。
  • 品质与掉线：BTHome / 开放协议传感尚可；强依赖手机蓝牙的「在家检测」误报多，重要安防不要只靠它。Proxy 请用以太网供电板，避免 Proxy 自己还去打 Wi‑Fi。
  • 地位：有则用之的边缘协议；不与 Z-Wave / Zigbee 抢门锁与墙开。

2.4.7 MQTT

角色：软件消息总线，不是无线制式。跑在 Ethernet / Wi‑Fi / IP 上；本宅在 Hub 上按需装 Mosquitto。Tasmota / ESPHome、部分墙面或 DIY 设备、以及日后 Zigbee2MQTT 都经它进 HA。

  • 优点：解耦生产者 / 消费者；保留历史状态与桥接老设备极灵活；局域网可完全本地。
  • 缺点：要自己管 Broker 账号、ACL 与发现约定（或依赖 HA 发现）；配置出错时「设备在线但 HA 无实体」难查；不是 end-user 产品协议。
  • 品质与掉线：Broker 与 HA 同机或同 VLAN 时极稳；跨 VLAN 忘放行 1883/8883、或设备 Wi‑Fi 本身漂，才会表现为 MQTT 掉线。
  • 地位：集成胶水层。ZHA 直连 Zigbee 时不必为 Zigbee 而装 MQTT；只有 Zigbee2MQTT / 大量 ESP 设备时才升格为基础设施。

2.4.8 Matter

角色：应用层互联标准（可跑在 Thread 或 Wi‑Fi / Ethernet 上）。HA 用 Matter Server 做本地控制器；Thread 设备经本宅 Border Router，Wi‑Fi Matter 设备经局域网委托。

  • 优点：多生态本地控制的长期方向；减少「每家一个桥」；与 HA 官方路径对齐。
  • 缺点：标准仍在猛迭代，真实设备质量两极；入网 / 共享 / OTA 失败故事仍多；「Matter」贴纸不保证好用——要看传输是 Thread 还是 Wi‑Fi、以及厂商固件态度。
  • 品质与掉线：认证灯泡 / 插座近年可用；复杂门锁、桥接器式「把旧射频包装成 Matter」的产品仍是重灾区。出问题先分清是 Thread 网、Wi‑Fi、还是 Matter 委托失败。
  • 地位：新设备采购的加分项，不是把现有稳定 Zigbee / Z-Wave 网推倒重来的理由。Matter-over-Thread 用第二根 ZBT-2；Matter-over-Wi‑Fi 不占用该棒。

4.2 备电与机柜 UPS

两台并联 Powerwall 3 解决的是全屋持续供电。机柜不再需要一台大容量 UPS 来撑整晚。UPS 只补两个缺口：Gateway 切换虽标 seamless，Tesla 没有承诺 UPS 级零中断，部分交换机 / NAS / 光猫可能在切换瞬间重启；以及 Powerwall 维护、故障或电量耗尽时，给 NAS 一个正常关机窗口。

  • 先确认机柜回路在 whole-home backup 范围内，并做一次离网切换测试。
  • 若 TELUS 光终端、Dream Machine Pro Max、Pro XG 24 PoE、NAS、HA 均不重启，可以不装 UPS。
  • 若摄像、门禁、HA、上网不能接受哪怕数秒中断，再加一台只桥接数分钟的小型 UPS，负荷按 UniFi 遥测和墙端实耗选，不要按含 180W Wallpanel 占位的规划总数选。
  • UPS 须能接受 Powerwall 离网时的电压/频率窗口；装完再测一次切换。

结论：双 PW3 前提下，UPS 从「强烈需要」降为「连续性保险」。参考 Gateway 3 Datasheet。
